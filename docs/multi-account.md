# 多账号设计与验收

## 使用流程

1. 在「账号与用量」中点击「保存当前账号」。凭据保存在 VS Code SecretStorage，列表只显示邮箱、套餐、备注和当前账号标识。
2. 点击「添加账号」打开官方浏览器登录。成功后自动保存新账号，登录期间可以取消。开始登录前先保存原账号的最新凭据，不调用注销接口。
3. 展开已保存账号，点击「切换」。检查当前官方连接内所有已加载会话，确认没有运行任务后保存当前凭据、原子替换登录缓存并重载当前 VS Code 窗口。重载后重新读取官方身份和用量，核对身份后才显示切换成功。
4. 备注只影响本地列表；移除只删除已保存副本，不注销当前登录。

## 范围

- 一次只有一个当前账号，当前窗口全部 Codex 标签共享该账号。Codex CLI、其他窗口或应用如果使用同一个 CODEX_HOME，也共用该登录缓存；本功能无法替其他进程停止任务或确认它们的状态。切换前结束共享缓存的任务并保存草稿。
- 首版支持可从官方连接确认的本地 CODEX_HOME、ChatGPT 登录、file 凭据存储。拒绝 keyring、auto、ephemeral、API Key、远程和 WSL，不修改用户配置来绕过限制。官方接口、系统加密存储或缓存身份无法确认时，不执行切换。
- 凭据仍可能过期或被服务端撤销，需要重新登录。官方负责正常的令牌刷新；保存或离开账号时更新已保存副本。
- 重载是当前官方扩展自身采用的连接重启方式。独立标签尚不保证重载后恢复到对应会话，发送过的会话可从历史重新打开，草稿需自行保存。
- 兼容范围沿用资产校验：未审计的官方资产不强行打补丁。已启用旧桥的窗口需先完成一次正常重载。

## 实现边界

- `src/accounts/account-store.js`：SecretStorage 账号仓库、身份校验、文件锁、0600 原子替换、条件回滚；不输出令牌或原始异常。
- `src/accounts/account-controller.js`：账号操作互斥、官方登录轮询/取消、重载与重载后身份核验。
- `src/compatibility/sidebar-bridge-patch.js`：专用账号动作、真实连接环境、全连接已加载会话预检。通用 RPC 白名单仍禁止凭据读取和任意登录方法。
- `src/sidebar/sidebar-controller.js`：账号操作与用量刷新、重置卡操作互斥；旧快照失效。
- `media/sidebar/`：保持现有布局和无障碍按钮；webview 消息只接受已知账号 ID，不接受凭据或路径。

账号库按 CODEX_HOME 分组；文件锁协调本扩展的多窗口操作，但不锁住官方 CLI 或其他应用。替换前核对缓存是否变化，回滚仅在文件仍属于本次写入时进行，避免覆盖外部更新。

运行任务检查是检查时刻的快照，官方没有提供跨面板的任务锁。添加账号后浏览器登录成功会由官方直接更新缓存，等待登录时不要启动新任务。文件最终读取和原子重命名也不是文件系统 CAS，无法完全排除其他进程恰在这两步间刷新令牌；请结束共用缓存的 CLI 和其他客户端任务后操作。

从 0.5.2 起，读取账号列表不持有写锁。写锁 `CODEX_HOME/.codex-multi-tab-account.lock` 内记录进程 ID 与随机所有者标识，只有确认该进程不存在时才自动回收。活进程、权限不足或无法确认所有者的锁不会被自动清理。0.5.0–0.5.2 遗留的空锁需要先确认旧宿主退出、锁未发生变化，再隔离该锁；通常可先退出全部使用该缓存的窗口和客户端，再对确认为空的旧锁执行 `rmdir`。不要删除 `auth.json` 或其他 `.codex` 文件。锁清理失败时切换会尝试条件回滚。

0.5.3 将锁创建及所有者写入、所有者删除及目录释放各自放在短同步临界段内，避免正常扩展宿主退出在异步步骤间留下空锁。强制终止或断电仍可能中断文件系统操作，因此不按锁的年龄自动删除未知空锁；既有空锁仍需根据原宿主退出和目录身份不变的证据处理。

## 本地安装与运行版本

0.5.3 修复了结果通知阻塞操作状态的问题：接口结果决定操作是否完成，随后释放操作状态并触发只读刷新；通知仅用于告知，是否关闭或显示失败均不影响完成状态。请求超时仍属结果未确认，不推断成功或失败，也不自动重复消费。消费前的确认对话框仍必须等待用户选择。账号错误仅按已知错误码展示固定安全文案，不显示底层异常或凭据。旧窗口已卡住时，需要在结束任务、保存草稿后重载以加载修复，不能把安装成功当作运行版本已更新。

市场尚未发布的新版本应以机器范围安装，排除该扩展的 Settings Sync；其他扩展仍正常同步：

```sh
code --install-extension dist/codex-multi-tab-0.5.4-mofyer.vsix --force --do-not-sync
```

本机曾发生设置同步在本地安装 0.5.0 和 0.5.1 后重新安装市场 0.4.4，日志安装来源为 `settingsSync`。仅核对安装命令成功或短时文件版本不足，需要确认 `metadata.isMachineScoped=true`，并在实际同步之后再次核对版本。

扩展开发宿主会优先加载 `--extensionDevelopmentPath` 指定的工作区源码，扩展详情页则可能显示市场安装版本。账号面板显示实际运行版本及“开发模式”，用于区分二者。正常窗口重载后使用已安装的新版本；开发宿主重载后使用工作区的新代码。

如果开发窗口通过 `--extensions-dir` 使用独立扩展目录，默认 CLI 安装不会更新那个目录。安装时应同时传入该窗口实际使用的 `--user-data-dir` 和 `--extensions-dir`；通过详情页的 Size 路径与 Version 核对安装目标。

## 验证策略

自动化使用合成账号、临时目录和官方协议替身，覆盖加密存储故障、身份不匹配、并发切换、符号链接、写入失败、条件回滚、运行任务阻断、取消登录、过期或未知登录、旧桥降级、用量竞态和 webview 凭据隔离。实包兼容测试只修改临时副本。

真实双账号 OAuth、操作系统安全存储和重载后的真实身份属于人工环境验收；自动化通过不能替代这些结果。开发阶段不切换用户正在使用的真实账号。

2026-09-17 开发验证结果：

- 25 个 JavaScript 文件通过语法检查；169 项测试中 167 通过，2 项因缺少官方 26.908.40401 完整安装资产而跳过，无失败。
- 集成测试串联真实侧栏控制器、桥与文件存储，验证保存 A/B、保留 B 最新凭据、切回 A、单次重载以及重建后确认 A；官方传输和系统 SecretStorage 使用替身。
- Chromium 中验证真实按钮消息、登录取消、互斥禁用、恶意标签的纯文本渲染和 300px 侧栏无横向溢出。
- 独立审查发现的异步登录销毁、取消失败、重载取消和锁清理异常均已补修复与测试；外部进程并发边界保留如上。

### 0.5.1 灰色入口修复验证

安装后发现官方扩展磁盘中的桥仍未声明 accounts 能力，另外本地合法的多行 notify 数组会触发旧存储层的保守解析拒绝。0.5.1 改用官方合并后的有效认证配置；每次操作与切换写入前重新核对目录、file 存储及工作区限制。环境错误现在分别说明原因，旧桥提示重载。

回归结果：25 个 JavaScript 文件语法通过，178 项测试中 176 通过、2 项完整官方资产测试跳过，无失败。含合法多行 notify 配置的真实侧栏/桥/存储集成链路通过。安装验收增加官方已打补丁资产与备份版本核对；运行中的旧宿主仍需重载窗口才能读取新桥。

### 0.5.2 本机修复验收

- 25 个 JavaScript 文件语法检查通过；186 项测试中 184 通过、2 项缺少完整官方资产而跳过，无失败。增加真实子进程退出、SIGKILL、并发锁恢复及运行版本展示测试，独立审查通过。
- 日志确认 Settings Sync 曾将普通安装目录中的 0.5.0、0.5.1 降回市场 0.4.4；机器范围安装 0.5.2 后，13:16:40 的自动同步完成，索引仍为 0.5.2 且 `isMachineScoped=true`。
- 当前开发窗口另用 `backups/sidebar-dev/extensions`，该目录也已安装 0.5.2 并排除同步。实际扩展详情页显示 Version 0.5.2、Source VSIX。
- 根据旧宿主退出日志、进程不存在及空锁身份不变的证据，将旧空锁可逆隔离；实际侧栏的保存、添加、另一账号切换按钮恢复可用，两个已保存账号保留。
- 当前会话仍运行于重载前的开发宿主；尚未中断此任务去重载或再次切换真实账号。结束任务后重载才能加载新的锁恢复逻辑及运行版本标签。

### 0.5.3 回归结果（2026-09-20）

- 25 个 JavaScript 文件语法检查通过；201 项测试中 197 项通过、4 项缺少旧版或缓存资产而跳过，无失败。官方 26.908.40401 安装资产副本的应用、幂等、修改保护与字节恢复测试通过。
- 覆盖成功/错误通知不关闭及通知显示失败，验证操作状态释放、只读刷新与不重复消费；仅消费前确认等待用户交互。
- 真实子进程在创建目录或删除所有者后排队正常退出，验证不再留下空锁；继续覆盖死亡进程回收、并发、未知锁拒绝、锁替换和释放失败回滚。
- 以上使用合成凭据、临时文件及官方传输替身，不等于真实双账号切换或真实重置卡消费验收。未为测试消耗用户重置卡或切换当前登录。
